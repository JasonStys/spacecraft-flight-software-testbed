# Version 1.1.0 portable application

Created by Jason Stys. This version includes the recovery-observability workflow: inspect onboard
mode/boot/counter changes, received witnesses, hidden transitions and uncertain timing without
turning missing observations into an invented event history.

## Download and launch

- Windows: versioned ZIP, extract the whole folder and run `SpacecraftFlightTestbed.exe`.
- Linux/macOS: versioned tar.gz, extract with a native tar utility and run `SpacecraftFlightTestbed`.
- Choose the actual OS and CPU in the filename. Verify its SHA-256 file and inspect `RELEASE.json`
  for application version, source commit, clean/dirty status and platform identity.

These are unsigned portable folders, not installers. Ordinary use bundles Python, the native
worker and the UI; no development commands or account are required. Keep OS protections enabled.
Default launch binds a fresh loopback port and opens the default browser. Stop it with Ctrl+C.
Nothing installs a service, changes an OS setting or migrates a user's optional history database.
Preserve earlier releases and history; the existing evidence/export schemas remain unchanged.

## Acceptance and release boundaries

The build now verifies the archive after extraction, including actual native CLI/API outcomes,
compiled assets and a real Chromium user journey through observability and JSON download. Source
browser tests remain a separate three-engine gate. Windows uses ZIP; tar.gz preserves PyInstaller's
POSIX links and execute bits. Three-OS package checks must all pass before publication.

Preparation requires exact clean main, coherent product versions and complete successful
Validation/CodeQL evidence. Existing versions cannot be retargeted. Upload verifies draft/source,
versioned asset names, archive metadata and SHA-256 without overwriting a public or existing asset.
The workflow creates a draft only; publication follows independent six-asset/digest review.

Local prerelease packages can honestly carry `source_dirty: true`; those do not authorize a
release. CI upload requires clean exact-source metadata. A local launch is not clean-machine
installation proof, universal OS compatibility or flight qualification. This is educational,
synthetic software with no hardware, real telemetry, guidance or operational control.
